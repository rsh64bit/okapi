Building a real-time operating system for RISC-V in Rust — roadmap
Toolchain: Andes RISC-V GCC
Language: Rust (no_std)
01
Set up Andes GCC toolchain
Install Andes' riscv32-elf-/riscv64-elf- GCC (AndeSight / RISC-V bare-metal SDK), plus Rust nightly target riscv32imac-unknown-none-elf for the kernel crate.
→
02
Boot & entry sequence
Write _start and the linker script (.ld) targeting the Andes core memory map; set stack pointer, clear .bss, set mtvec, jump into Rust #[no_main].
→
03
Trap / interrupt handling
Handle machine-mode traps via mcause/mepc; wire Andes' vectored PLIC/CLINT (and AndeStar extensions if targeting an N/D/A45 core) for timer & external IRQs.
→
04
Task / thread abstraction
Define a Task struct with its own stack + saved context; implement the context-switch routine in GCC-compatible inline/naked asm callable from Rust.
→
05
Scheduler
Preemptive fixed-priority or round-robin scheduler driven off the machine timer (mtimecmp); add priority queues, then rate-monotonic/EDF later.
↳
10
Test, validate & benchmark
Boot on Andes QEMU model / AndeSim and real Andes silicon; measure interrupt latency & context-switch time; automate boot tests in CI.
→
09
Syscall / API surface
Define the ecall syscall ABI for task create, delay, IPC, I/O; expose a safe Rust API on top for application code.
→
08
HAL & driver layer
Abstract UART/timer/GPIO/PLIC behind a HAL so the kernel targets multiple Andes-based boards without core changes.
→
07
Memory management
Static/pool allocator for kernel objects & per-task stacks; optional PMP-based memory protection for isolation.
→
06
Synchronization primitives
Mutexes, semaphores, message queues safe under Rust ownership; atomics or interrupt-disable critical sections for mutual exclusion.

Okapi RTOS

Rust toolchain setup for the Andes N25F (32-bit RISC-V)
Core: Andes N25F (RV32IMAFC*)
ABI: ilp32 / soft-float first
01
Confirm ISA extensions
N25F configs vary — verify exactly which of M/A/F/C are enabled from the SoC datasheet before picking a target. Drives every choice below.
Assuming an extension the core lacks → illegal instruction at runtime.
02
Rust target & toolchain
Start with a stock soft-float target to de-risk bring-up:
rustup target add \
  riscv32imac-unknown-none-elf
rustup component add llvm-tools-preview
cargo install cargo-binutils
03
Linker config
.cargo/config.toml — use rust-lld (ships with rustc), point at riscv-rt's linker script:
[build]
target = "riscv32imac-unknown-none-elf"
[target.riscv32imac-unknown-none-elf]
rustflags = ["-C","link-arg=-Tlink.x"]
04
Runtime crates
Startup/vector table + CSR access:
[dependencies]
riscv = "0.11"
riscv-rt = "0.12"
panic-halt = "0.2"
05
Memory map
riscv-rt needs a memory.x with real FLASH/RAM regions pulled from the Andes SoC's memory map — no generic default exists.
Placeholder addresses will link but won't boot on real silicon.
06
Andes interrupt model
N25 uses AndeStar V5 trap/CSR extensions (vectored mtvt, mmisc_ctl), not a stock SiFive CLINT/PLIC. Stock riscv-rt trap handling may need patching to vector correctly.
07
Hardware float (later)
No tier-2 target matches rv32imafc/ilp32f exactly. Requires a custom target-spec JSON + nightly -Z build-std once soft-float bring-up works.
rustc -Z unstable-options \
  --target riscv32imac-unknown-none-elf \
  --print target-spec-json \
  > riscv32imafc.json
# edit: features "+m,+a,+f,+c"
#       llvm-abiname "ilp32f"
08
Validate before silicon
Prove the build/link pipeline with QEMU's generic virt machine (approximate, not Andes-exact) before flashing real hardware.
qemu-system-riscv32 -machine virt \
  -nographic -kernel target/.../fw
